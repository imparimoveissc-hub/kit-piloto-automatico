0TL;DR

A Traffic Stack vive em Kit-Piloto-Automatico-V30/11_TRAFFIC_STACK/. Pra usar:

  1. Abre PowerShell (Windows) ou Terminal (macOS/Linux) na raiz Kit-Piloto-Automatico-V30/
  2. Roda claude
  3. Cola o prompt-pai (seção 4)
  4. Pede o que quer (*diagnostico 7d, *kill-list, etc.)
  5. Confirma toda ação destrutiva (pause/edit/budget)
Nota terminológica "MCP do Meta" e "Ads CLI" não são a mesma coisa. Aqui usamos o CLI Python meta-ads oficial (rodando nativamente no macOS/Linux ou via WSL no Windows). O Windows usa o wrapper <HOME>\bin\meta.cmd que roteia comandos pro WSL transparentemente. Pra instalar tudo do zero, rode /meta-cli-install dentro do Claude Code.

1O que é a Traffic Stack

Camada operacional dentro do Kit Piloto Automático V30. Enquanto o resto do kit (CoS, agents de copy, pipeline) está orientado a criar campanhas (briefing → estrutura → criativo → subir), a Traffic Stack é orientada a operar campanhas vivas:

  • Diagnóstico de queda de performance
  • Análise de criativos (hook rate, retention, padrão vencedor)
  • Auditoria de tracking (Pixel + CAPI saúde)
  • Escala de vencedores (ABO/CBO/Oxigênio/horizontal/multi-account)
  • Inteligência competitiva (Meta Ad Library, swipe, engenharia reversa)
  • Análise de funil end-to-end (ads → LP → VSL → quiz → checkout)

A stack é multi-conta por design: cada cliente em 05_WORKSPACE/clientes/<cliente>/ tem context próprio (CLAUDE.md, act-mapping.yaml, funil.md, icp.md, baseline-kpis.md). O orchestrator carrega o context certo antes de qualquer análise.

2Pré-requisitos (verificar 1× só)

2.1 — CLI Meta funcionando

Rodar no PowerShell pra confirmar:

& "<HOME>\bin\meta.cmd" auth status

Esperado: Authenticated (token: EAA<SEU_TOKEN_TRUNCADO>). Se não, token expirou — gerar novo System User Token no Business Manager e atualizar ~/.profile do WSL (variável ACCESS_TOKEN).

2.2 — WSL ativo

wsl --list --quiet

Esperado: Ubuntu. Se WSL travou: wsl --shutdown e tenta novamente.

2.3 — Estrutura do Kit presente

cd <PASTA_DO_KIT>\Kit-Piloto-Automatico-V30
ls 11_TRAFFIC_STACK\agents
ls 05_WORKSPACE\clientes\<seu-cliente>

Esperado: 8 arquivos de agente em agents/ e 5+ arquivos na pasta do seu cliente.

2.4 — Cliente configurado

Antes de usar a stack pra qualquer cliente, garantir que existe 05_WORKSPACE/clientes/<cliente>/ com:

3.2 — Prompt-pai (cola tudo)

Esse é o prompt mestre que invoca a stack. Cola no Claude Code recém-aberto:

Lê 05_WORKSPACE/clientes/<seu-cliente>/CLAUDE.md + act-mapping.yaml + funil.md + icp.md inteiros 3. Lê 11_TRAFFIC_STACK/tasks/diagnosticar-campanha-meta-cli.md (pipeline a executar) 4. Confirma o greeting do orchestrator e me lista os comandos disponíveis Auto mode ON. Pode rodar CLI sem perguntar (só leitura). Confirma comigo antes de QUALQUER ação destrutiva (pause/edit/budget). Fala em pt-BR. Acentuação 100% correta.

Após esse prompt, o Claude vai assumir a persona do @traffic-orchestrator e listar os 8 comandos. A partir daí, você pede o que quiser.

3.3 — Variantes de abertura

Aciona @traffic-orchestrator pra cliente <outro-cliente>. Roda *diagnostico 14d. Filtra produto principal.

4.1 — Como invocar um agente diretamente

Em vez de passar pelo orchestrator, você pode acionar agente específico:

Aciona @creative-analyst — leia 11_TRAFFIC_STACK/agents/creative-analyst.md e adota essa persona. Cliente: <seu-cliente>. Roda *dna nas 3 campanhas <PRODUTO> dos últimos 14 dias.

4.2 — Como o handoff entre agentes funciona

Cada agente sabe pra qual outro agente delegar. Exemplo: @meta-dr-specialist identifica vencedor → handoff pra @scaling-strategist → escala via @creative-analyst (lateralização). Você não precisa orquestrar manualmente — o orchestrator e os agentes coordenam.

ReativoAlgo caiu — investigação forensic
CPA disparou / ROAS despencou / vendas sumiram
Aciona @traffic-diagnostician. Cliente: <seu-cliente>, produto <PRODUTO>. Sintoma: [DESCREVA O QUE VOCÊ TÁ VENDO]. Roda *investigar — quero árvore de hipóteses ranqueada por probabilidade + ação imediata.

Investigação em 6 camadas (em ordem):

  1. Tracking — Pixel/CAPI quebrou? Atribuição mudou?
  2. Criativo — saturação? hook rate caindo?
  3. Audience — overlap? exclusion errada?
  4. Oferta — preço mudou? bônus removido?
  5. Funil — LP/VSL/checkout quebrou?
  6. Externo — sazonalidade? mudança Meta? competição?

Não pula camada. Cada hipótese precisa evidência antes de virar conclusão.

6CLI meta — referência rápida

Se quiser rodar comandos diretamente no terminal (sem agente), aqui as receitas mais usadas. Path do wrapper: <HOME>\bin\meta.cmd.

6.1 — Anatomia do comando

meta <grupo> <recurso> <ação> [--flags]
meta ads     campaign  list
meta ads     adset     get      <ID>
meta ads     insights  get      --date-preset last_7d
meta auth    status

6.2 — Receitas leitura SEGURO

Listar todas campanhas ativas

& "<HOME>\bin\meta.cmd" ads campaign list `
  --ad-account-id act_XXXXXXXXXXXXXXX `
  --filter "effective_status=ACTIVE" `
  -o json

Performance dos últimos 7 dias (nível campanha)

& "<HOME>\bin\meta.cmd" ads insights get `
  --ad-account-id act_XXXXXXXXXXXXXXX `
  --date-preset last_7d `
  --level campaign `
  --fields spend,impressions,clicks,ctr,cpc,cpm,actions,purchase_roas `
  -o json

Top 10 ads ordenados por gasto

& "<HOME>\bin\meta.cmd" ads insights get `
  --ad-account-id act_XXXXXXXXXXXXXXX `
  --date-preset last_14d `
  --level ad `
  --sort spend_descending `
  --limit 10 `
  -o json

Detalhes de um ad específico (com creative)

& "<HOME>\bin\meta.cmd" ads ad get <AD_ID> -o json
& "<HOME>\bin\meta.cmd" ads creative get <CREATIVE_ID> -o json

Listar contas que o token tem acesso

& "<HOME>\bin\meta.cmd" ads adaccount list -o json

6.3 — Receitas escrita DESTRUTIVO

Confirma SEMPRE antes Pause/edit/budget/delete via CLI mexem em campanhas reais. Não rodar em automação cega. Sempre validar o ID alvo, ler o efeito esperado, e só executar com confirmação humana.

Pausar uma campanha

& "<HOME>\bin\meta.cmd" ads campaign update <CAMPAIGN_ID> --status PAUSED

Ativar uma campanha (após validar tudo)

& "<HOME>\bin\meta.cmd" ads campaign update <CAMPAIGN_ID> --status ACTIVE

Mudar budget diário (CBO)

# Limite recomendado: max +20-30%/dia. Nunca dobrar.
& "<HOME>\bin\meta.cmd" ads campaign update <CAMPAIGN_ID> --daily-budget 60000
# 60000 = R$ 600,00 (em centavos)

Quando ir pra Graph API:

7Multi-conta — operar várias contas

7.1 — Estrutura

O CLI aceita --ad-account-id act_OUTRO_ID em qualquer comando. A stack mantém o mapeamento em dois lugares:

  • 00_OS/clients-map.yaml — mapa global act_id ↔ cliente
  • 05_WORKSPACE/clientes/<cliente>/act-mapping.yaml — todas as contas daquele cliente (alguns têm múltiplas)

7.2 — Conta unificada (multi-produto)

É comum o operador rodar vários produtos próprios numa mesma conta de anúncios. Convenção recomendada:

  • <PRODUTO_A> — descrição
  • <PRODUTO_B> — descrição
  • <MARCA_PESSOAL> — topo de funil
  • Outros produtos — adicionar conforme lançar

Filtragem por produto via naming convention das campanhas:

# Campanhas do produto A
meta ads campaign list --ad-account-id act_XXXXXXXXXXXXXXX `
  --filter "name:CONTAINS=PRODUTO_A_" -o json

# Campanhas do produto B
meta ads campaign list --ad-account-id act_XXXXXXXXXXXXXXX `
  --filter "name:CONTAINS=PRODUTO_B_" -o json

7.3 — Adicionar nova conta

Pra integrar uma conta nova (ex: cliente da agência):

  1. Atribuir conta ao System User no Business Manager (BM → Configurações → Usuários do Sistema → Atribuir Conta de Anúncios)
  2. Validar acesso: 
    & "<HOME>\bin\meta.cmd" ads adaccount get act_NOVO_ID -o json
  3. Pedir pra criar context em sessão Claude Code (ver workflow "Adicionar conta nova")

7.4 — Multi-cliente — caso de agência

Cada cliente tem sua pasta. Cria conforme adiciona contas:

05_WORKSPACE/clientes/
├── <cliente-1>/                # sua marca / produto principal
├── <cliente-2>/                # cliente da agência
├── <cliente-3>/                # ...
└── <cliente-N>/                # um por act_id ou um por marca

Antes de qualquer análise, agente lê o CLAUDE.md do cliente alvo. Nunca misturar context entre clientes — cada um tem ICP, baseline, restrições próprias.

8Regras inegociáveis

1. Paused-First Toda criação (campanha/adset/ad) inicia em status: "PAUSED". Validar no Gerenciador. Ativar só depois com confirmação. Sem exceção.
2. Confirmação destrutiva Pause / edit / delete / mudança de budget >20% — agente lista a ação proposta e PEDE confirmação antes de executar. Mesmo em auto mode.
3. Cliente context obrigatório Sem 05_WORKSPACE/clientes/<cliente>/CLAUDE.md carregado, agente recusa executar análise. Não usar benchmark genérico quando há baseline próprio.
4. Dados reais sempre Nenhum agente inventa número. Se CLI falha, agente reporta erro e para. Sem estimativas mascaradas de fato.
5. pt-BR coloquial, acentuação 100% Output em pt-BR (estilo Pedro, não corporativo). Acentuação correta — NUNCA passar texto pt-BR inline em curl no Windows (UTF-8 quebra). Salvar em arquivo JSON via Write antes.
6. VTurb anti-loop Toda mexida em LP que tem VSL VTurb precisa passar pelo checklist ~/.claude/rules/vturb-embed.md. Sem isso, VSL fica recarregando infinito. (Aplica também a Panda Video, Vimeo, YouTube embeds.)
7. Frameworks tier 1 padronizados Todos seguem: (1) DRE 5 níveis, (2) Funil 4 estágios, (3) "Onde Quebrou?" decision tree, (4) Andrômeda Era (Meta API v25). Sem invenção.
